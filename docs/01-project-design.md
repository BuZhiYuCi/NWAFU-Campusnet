# 校园网一键登录 / 一键下线 客户端 —— 项目设计

文档状态：设计稿 v2.0（2026-09-15，已按第二轮需求确认重写）
目标平台：Windows 10 / 11（x64）
适用对象：西北农林科技大学 深澜（SRun）校园网门户 172.26.8.11

---

## 1. 需求确认

### 1.1 场景

学校校园网对单个账号同时在线设备数有限制。用户手上设备数量不固定（可能超过 3 台），
需要随时决定"现在哪几台在线"，而不是被"先来先占"的会话卡住。

关键事实：**断开 WiFi / 拔网线 ≠ 下线**。实测本账号的两个会话从 2026-09-12 一直保持到
2026-09-15（3 天），说明服务端会长期保留在线会话。把网卡禁用、关机、拔网线之后，
会话仍然占着名额——这正是"必须真正调用注销接口"的原因。

### 1.2 功能需求

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| R1 | 一键登录（本机） | 双击/点一下即完成认证，不需要打开浏览器、不需要输网址账号密码 |
| R2 | 一键下线（本机） | 真正调用注销接口解除在线会话，不是禁用网卡/断开连接 |
| R3 | 查看在线设备列表 | 列出本账号所有在线设备：IP、设备类型、操作系统、上线时间、已在线时长 |
| R4 | 选择一台或多台设备下线 | 在列表中勾选任意数量，批量注销 |
| R5 | 满员时引导腾位 | 登录返回"在线数已满"时，自动弹出设备列表让用户勾选下线，然后自动重试登录 |
| R6 | 账号密码可设置/保存/修改 | 首次设置一次，之后每次直接用；随时可修改；加密保存 |
| R7 | 开机自启（可开关） | 用户自己决定是否开机启动；启动后只驻留托盘，不自动认证 |
| R9 | 状态显示 | 托盘图标 + 主窗口显示：不在校园网 / 已离线 / 已在线，支持手动刷新 |
| R10 | 全局热键（可选） | 例如 Ctrl+Alt+L 登录、Ctrl+Alt+K 下线 |

### 1.3 明确不做

| 项 | 说明 |
| --- | --- |
| 不做自动守护 / 断线自动重连 | 用户明确排除。本工具只在用户点击时动作，不做后台循环认证 |
| 不做开机自动认证 | 设备既有 WiFi 也有网线，网络环境不一致，由用户自行连好网后再手动认证 |
| 不做后台高频踢人 | 不允许静默循环互踢；所有下线动作都由用户勾选触发或用户确认 |
| 不做多账号 | 暂不需要；配置结构预留，后续可扩展 |
| 不做关机自动下线 | 用户决定取消：由用户自己在关机前点一下"一键下线" |
| 不修改/攻击学校服务器 | 只调用门户官方网页自己也在调用的公开接口 |

### 1.4 硬约束（实测得出，直接决定架构）

1. **登录必须在本机执行。** 登录接口的 ip 参数必须是发起请求那台机器自己的 IP，
   服务端会校验（错误码 E6514：IP 与认证地址不符，可能经过小路由器）。
   所以"A 机器替 B 机器登录"在协议层不成立，每台要上网的设备都得装一份。
2. **但下线/踢人不受此限制。** 任意设备（包括尚未认证、处于离线状态的设备）都能访问门户、
   查询在线列表、注销指定设备。这是"新设备满员时自助腾位"的前提。
3. **IP 是动态的。** DHCP 分配，会变化，不能当作设备唯一标识；在线列表里也没有主机名和 MAC。

```
├──────────────────────────────────────────────────────────────┤
```

设计原则：

1. 协议层零 UI 依赖，CLI / GUI / 测试脚本共用同一套代码。
2. 网络请求同步、显式超时，由上层用线程调度，UI 不阻塞。
3. 除 requests 外全部使用标准库（hmac / hashlib / ctypes / tkinter），便于打包成单文件 exe。

## 4. 核心流程

### 4.1 一键登录（本机）

```
[用户点"登录"]
      │
      ▼
1. 检查 172.26.8.11 是否可达 ──── 不可达 ──► 提示"当前不在校园网，请先连好网线/WiFi"
      │ 可达
      ▼
2. 登录前自检 GET /cgi-bin/rad_user_info?callback=cb（按来源 IP 查）
      │
      ├─ 未在线 ─────────────────────────► 走第 3 步正常登录
      │
      ├─ 在线且 user_name == 本账号
      │      └─► 本机 IP 的会话仍存在（多半是上次关机没下线）
      │          提示"当前已在线"，并提供两个按钮：
      │            · 直接使用（不动作）
      │            · 重新认证（先注销再登录，用于会话异常时刷新）
      │
      └─ 在线且 user_name != 本账号
             └─► 本机 IP 被其它账号占用（DHCP 回收后分给了别人）
                 提示"IP 已被占用"，建议等待或重连网络以获得新 IP
      │
      ▼
3. GET /cgi-bin/get_challenge?username&ip → 取 token（60 秒有效）
      │
      ▼
4. 计算 hmd5   = HMAC-MD5(key=token, msg=password)
   计算 info    = "{SRBX1}" + 自定义Base64(XXTEA(json, key=token))
   计算 chksum  = SHA1(token+u+token+hmd5+token+acid+token+ip+token+n+token+type+token+info)
      │
      ▼
5. GET /cgi-bin/srun_portal?action=login&...（参数详见协议文档）
      │
      ├─ ecode == 0 ────────────────────────► 登录成功
      ├─ ecode 属于 {E2620, E2621, E6512} ──► 走【4.3 满员腾位】
      ├─ E2532（两次认证间隔太短）──────────► 冷却 10s 后自动重试一次
      ├─ E2611 / E2614（绑定限制）──────────► 提示去自助服务绑定
      └─ 其它 ──────────────────────────────► errors.py 翻译为中文提示
```

登录是幂等的：已经在线时点"登录"不能报错。

### 4.2 一键下线（本机）

```
[用户点"下线"]
      │
      ▼
1. GET /cgi-bin/rad_user_info?callback=cb → 取真实 online_ip 与在线状态
      │   （不盲信本地网卡枚举结果；服务端看到的 IP 才是准的）
      │
      ├─ 已不在线 ──► 提示"当前已离线"，结束（幂等）
      │
      ▼
2. GET /cgi-bin/srun_portal?action=logout&username=<账号>&ip=<online_ip>&ac_id=<ac_id>
      │
      ▼
3. 确认：每秒查一次 rad_user_info，最多 5 次，直到确认离线
      │
      └─ 5 秒仍未确认 ──► 报"注销请求已发送但未确认"，提示可重试
```

关键点：这一步调用的是服务端的注销接口，会真正释放在线名额。
点"禁用网卡"或"断开 WiFi"做不到这件事。

**已按实测修正（Phase 3）**：具体用哪个接口取决于机制，见
[03-logout-mechanisms.md](03-logout-mechanisms.md)：

| 机制 | 效果 |
| --- | --- |
| `rad_user_dm`（unbind=1）**默认** | 连 MAC 免认证绑定一起解除，真正下线，实测 67 秒保持离线 |
| `action=logout`（配置可切回） | 只注销会话；本机 MAC 若开了免认证会被同一秒拉回，外网一秒不断 |

所以流程实际是：取本机 IP → 发 dm 注销 → 轮询确认（限流时用设备列表判定）→
确认不掉线就如实报"仍在线"，不谎报成功。

### 4.3 满员腾位（查列表 → 勾选 → 批量下线 → 重试登录）

触发条件：登录返回 E2620 / E2621 / E6512（已经在线 / 已达授权人数 / 在线用户已满）。

```
[登录返回满员]
      │
      ▼
1. GET /v1/srun_portal_online?user_name=<账号>&password=<md5(密码)>
      │   ← [{ip, os_name, client_type, add_time, user_name}, ...]
      ▼
2. 弹出【在线设备管理】窗口，表格展示：
      │   ☐ | # | IP | 设备类型 | 操作系统 | 上线时间 | 已在线时长 | 备注
      │   本机 IP 那一行标灰并注明"本机"
      │   已在线时长 = 服务端当前时间 - add_time，按 天/小时/分钟 显示
      ▼
3. 用户勾选一台或多台 ──► 点【下线所选】
      │   （支持全选、按在线时长排序、按上线时间排序）
      ▼
4. 串行批量执行 GET /cgi-bin/rad_user_dm?ip=..&username=..&time=..&unbind=1&sign=..
      │   每台之间间隔约 0.8 秒；逐行显示结果（成功 / 失败原因）
      ▼
5. 刷新设备列表确认名额已释放 ──► 自动回到 4.1 重新登录
      │
      └─ 仍失败 ──► 最多重试 2 次，然后明确报错，不做无限循环
```

UI 上的两种交互模式（设置里切换）：

| 模式 | 行为 | 默认 |
| --- | --- | --- |
| preselect_oldest（预选最早） | 弹出列表，并自动勾选**上线时间最早（即在线时间最长）**的那台；用户可改选、可加选，确认后执行 | 是（默认） |
| manual（纯手动） | 弹出列表，不预选，完全由用户自己勾选 | 可选 |

无论哪种模式，**都不会在用户不知情的情况下踢设备**：默认模式下"最早那台"只是被预先勾上，
用户点确认才会真正下发注销请求。

保存的默认勾选逻辑：

- 按 add_time 升序排列，勾选第一台（上线时间最早）。
- 若该台就是本机 IP，则顺延勾选下一台（避免"预选自己"这种无意义的选择）。
- 用户上一次手动调整过的勾选结果不会持久化，每次弹出都按此规则重新计算。

### 4.4 开机自启（用户可开关）

> 原先设计的"关机自动下线"（拦截 WM_QUERYENDSESSION）**已按用户决定取消**：
> 关机前由用户自己点一下"一键下线"即可。少一个常驻的消息钩子，
> 程序也少一类"关机时卡住"的风险。

- 开关位置：设置页里的"开机自动启动"，默认**关闭**，由用户主动打开。
- 实现：写/删注册表 HKCU\Software\Microsoft\Windows\CurrentVersion\Run。
  只影响当前用户，不需要管理员权限。
- 命令行也能开关：`campusnet autostart on|off|status`。
- 行为：启动后**只把程序跑起来，不自动认证、不自动下线**。用户连好网后自己点"一键登录"。
- 启动后的形态由设置项控制（见下）。**已确认：程序启动时弹出主窗口。**

注册的命令分两种（见 `autostart.build_command`）：

| 场景 | 注册的命令 |
| --- | --- |
| 跑源码 | `"<pythonw.exe>" "<仓库>\run_gui.pyw"`（用 pythonw 不弹黑窗口；脚本自己把 src 加进路径，不依赖 PYTHONPATH） |
| 打包成 exe 后 | `"<exe 路径>"` |

带 `--tray` 参数时静默启动（只留托盘，不弹主窗口）。

**启动方式与"是否弹窗"是两件独立的事**：

| 设置项 | 含义 | 默认 |
| --- | --- | --- |
| startup.autostart | 开机时是否自动把本程序跑起来（只启动，不认证） | 关 |
| startup.open_window_on_start | 程序启动时是否弹出主窗口；关闭则只出现在右下角托盘区 | **开（弹窗）** |
| startup.silent_when_autostart | 开机自启那一次是否静默（不弹窗），其余启动照常弹窗 | 关（也弹窗，与手动启动一致） |

也就是说：默认情况下，程序一启动就弹出主窗口，你可以直接点"一键登录"或"一键下线"。
窗口关闭后程序不会退出，而是缩到右下角托盘区继续待命，双击托盘图标或按热键可以再打开。
如果以后觉得开机自启时弹窗碍事，把 silent_when_autostart 打开即可，手动双击仍然照常弹窗。

## 5. 配置设计

存放位置：%APPDATA%\CampusNet\config.json （不放程序目录，避免只读目录与多用户干扰）。

```jsonc
{
  "version": 2,
  "portal": {
    "base_url": "http://172.26.8.11",
    "ac_id": 1,
    "username": "20230000001",        // 用户可随时在设置页修改
    "domain_suffix": "",              // 待 Phase 0 实测：可能为空或 "@yx-s-student"
    "password_dpapi": "<BASE64-DPAPI密文>",   // 明文密码永不落盘
    "os_name": "Windows 10",          // 登录参数 os
    "client_name": "Windows",         // 登录参数 name
    "timeout_sec": 8
  },
  "behavior": {
    "kick_mode": "preselect_oldest",  // preselect_oldest（默认，预选上线最早那台）| manual
    "logout_method": "dm",            // dm（默认，真正下线）| portal（会被 MAC 免认证拉回）
    "confirm_before_kick": true,
```

## 6. 安全设计

| 风险 | 对策 |
| --- | --- |
| 明文密码落盘 | Windows DPAPI（CryptProtectData，当前用户级）加密后存 Base64，配置文件里只有密文 |
| 密码出现在日志/命令行 | 日志统一脱敏：密码、password= 参数、token 全部替换为 *** |
| 密码经 HTTP 传输 | 门户本身即 HTTP；登录参数中密码以 HMAC-MD5 + XXTEA 密文传输。但在线设备查询接口会把 md5(密码) 放进 URL（门户自身设计），因此该接口只在校园网内调用且不写日志 |
| 配置被他人读取 | DPAPI 绑定当前 Windows 用户，换用户/换机器无法解密 |
| 配置文件误入版本库 | .gitignore 忽略 config.json、*.log、dist/、build/ |
| 误踢设备 | 默认 manual 模式 + confirm_before_kick；列表显示 IP 与上线时间；所有下线动作写审计日志 |
| 触发服务端风控 | 请求全程串行 + 冷却时间 + 密码错误计数熔断（3 次即停） |
| 开机自启被滥用 | 只写 HKCU Run 项，用户在设置页可一键关闭；程序自身不自动认证 |

账号信息不写入任何文档和源码，只在运行时由用户输入并加密保存。

#### Phase 0 的执行方式（断网安全设计）

**第一步不需要断网。** 本机当前已在线，可以在这个状态下直接发一次登录请求当作"探针"：

| 服务端返回 | 说明 |
| --- | --- |
| 签名错误 / 参数错误 / 解密失败 | 说明我们的算法不对 → **不断网就发现了**，继续调整后再试 |
| 已在线类错误（E2620 / E6526 / ip_already_online_error） | 说明签名与加密**已被服务端接受**，算法正确性得到验证，且全程没有断网 |

也就是说，0.1/0.2/0.3/0.4 这四项可以第一次就验证完，风险接近零。

**第二步才需要真实断网**，验证 0.5 / 0.6 / 0.7 / 0.8。
为不误伤其它设备，DM 下线测试的**目标改成本机自己的 IP**：
这样既验证了签名算法，又顺带完成了本机注销，**完全不需要动 10.111.147.127 那台设备**。
（若用户仍希望验证"踢别人"，再单独执行一次即可。）

**探测脚本必须写成"一次启动、离线也能自己跑完、结果全部落盘"的形式**，原因见下：

> 脚本本身跑在这台机器上，断网不影响它执行——校园网门户 172.26.8.11 在**未认证状态下依然可访问**
> （这正是"连上 WiFi 会跳出认证页"的机制）。所以注销之后，脚本仍然能查设备列表、能重新登录。
>
> 但**AI 助手本身是在云端运行的**，通过 Codex 应用与这台机器通信。本机一断网，
> AI 就收不到工具输出、也无法下发新命令。因此断网期间必须让脚本自己完成全部步骤并写日志，
> 等网络恢复后再由 AI 读取日志复盘。

执行步骤：

1. 写入探测脚本 tools/probe.py，输出目录 docs/phase0-report.md（含每一步的原始请求参数与响应）。
2. 后台启动脚本（本机进程，与 AI 会话解耦），AI 随后等待。
3. 脚本自行完成：DM 注销本机 → 确认离线 → 查在线设备列表 → 重新登录 → 确认恢复在线。
4. 预计断网时长 10~30 秒。网络恢复后 AI 读取报告，确认每一项的结论。
5. 兜底：万一算法不对导致没能自动恢复，用浏览器打开门户手动登录一次即可恢复
   （平时怎么登，现在就怎么登），随后 AI 读报告定位差异。

交付物：docs/02-portal-protocol.md 中"待实测"标记全部改为实测结论，外加 docs/phase0-report.md 实测报告。

本阶段推翻了一个原设计决定（详见 `docs/03-logout-mechanisms.md`）：

> **"一键下线"不能用 `action=logout`。** 实测：本机 MAC 开通了校园网免认证，
> `action=logout` 只注销 RADIUS 会话，准入设备在同一秒就用 MAC 把设备重新认证上线——
> 外网一秒都没断（设备列表里立刻出现 `client_type=6 / MAC auth`）。
> 必须用 `rad_user_dm`（unbind=1），它会连 MAC 绑定一起解除，实测 67 秒全程保持离线。
> 因此新增配置项 `behavior.logout_method`，默认 `dm`。

同时修掉了两个由自己造成的坑：

- `rad_user_info` 会被限流（`speed_limit_error`），把"查不到"当"离线"会误报失败；
  现在状态判定是三态（在线/离线/未知），限流期间改用**不受限的设备列表**判定，
  并设置 60 秒冷却避免轮询给限流续期。
- 确认状态的轮询间隔从 1.5 秒放宽到 2 秒并按限流退避。

### Phase 7 之后修掉的一个实际用户 bug

用户反馈：**首次运行弹出设置向导，填完保存后主窗口一直卡在"正在检测…"**，
强制结束再打开才正常。排查下来是两个 bug 叠在一起：

1. **没有密码时仍然去查在线设备列表**——那个接口需要 `md5(密码)`，
   密码为空时直接抛 `AttributeError`。
2. **`TaskRunner` 里写成了 `lambda: fail(exc)`**。Python 3 在 `except` 块结束时会删除
   异常变量 `exc`，所以这个 lambda 真正执行时抛 `NameError`；而事件泵里加的
   "回调出错别崩" 的兜底把它**静默吞掉**了 → `_busy` 永远停在 True →
   界面卡死，后续刷新因为"正在忙"被直接跳过。

修法：

- `crypto.password_md5()` 遇到空密码给出明确错误，不再抛 `AttributeError`；
- GUI 在**没有凭据时不查设备列表**；
- lambda 用默认参数绑定值（`lambda e=exc: fail(e)`，`lambda r=result: done(r)`）；
- 事件泵不再静默吞异常，改为写日志（否则这类 bug 极难发现）；
- `fail` 回调用 `finally` 保证一定会解除忙碌状态。

顺带改进：设置对话框自动聚焦账号框，**回车即保存**、Esc 关闭；
新增 **`CampusNet.exe --selftest` 界面自检**——在真实窗口里离线走一遍
"首次设置 → 保存 → 刷新"，结果写进日志并弹窗显示。
用户再遇到"界面卡住"可以一键自查。

回归测试：新增 4 项（后台任务失败必须解除忙碌、异常值在回调里可读、
首次设置流程能恢复、无凭据刷新不报错），总计 **186 项测试**，
打包后的 exe 自检也通过。

### 11.4 按钮：从"生硬的方框"改成圆角胶囊

tk 自带按钮在 Windows 上是直角硬边、悬停只有生硬的高亮，观感很"硬"。
新增 `src/campusnet/ui/widgets.py` 里的 `RoundedButton`：

- 用 **Pillow 画圆角矩形**（竖向渐变 + 细描边），4 倍超采样后 LANCZOS 缩小，
  得到平滑边缘；tkinter 的 Canvas 本身没有抗锯齿，靠这一步解决；
- 自己接管 **常态 / 悬停 / 按下 / 禁用** 四种状态（各自一套渐变色）；
- 三种风格：`accent`（实心绿主按钮）、`soft`（淡绿次级）、`ghost`（无底，悬停才浮出淡绿）；
- 接口对齐 `tk.Button`：`configure(state=/text=/command=)`、`invoke()`、`.state`，
  所以既有的 `_set_busy()` 之类逻辑不用改。

只缓存与解释器无关的 **PIL 图像**；`PhotoImage` 每个按钮各建一份——
Tk 的图像绑定到具体解释器，放全局缓存会在窗口重建后报 "image doesn't exist"
（写测试时踩到）。

`tests/test_widgets.py`（12 项）验证：渐变方向（上亮下暗）、圆角外像素透明、
悬停底色与常态不同、禁用时不触发命令、移出按钮再松手不触发、
按钮宽度随文字变化、幽灵按钮常态无底色。

**第二轮调整（按用户反馈）**：

- 圆角从"胶囊"（= 高度的一半，36px 按钮就是 18px）**收到 9px**，
  变成"略带弧度"的圆角矩形；实测顶行内缩从 14px 降到 6px。
- 按钮字号从 10 磅提到 **11 磅**，主按钮（一键登录/保存/下线并继续登录）加粗；
  次级小按钮用 10 磅。字号统一挪进 `theme.FONT_*` 常量，
  状态大字 17、小标题 11、正文 10、说明 9，全界面共用一套。
- 中文在行框里整体略偏下，文字位置上移 1px 做视觉居中。

  否则每个按钮每次重绘都新建图片，窗口销毁后被 GC 时会刷一屏
